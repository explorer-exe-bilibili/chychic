# 上下位机通信协议 v1.0

> 上位机（ARM64 Linux / 树莓派 / RK）= 算法，下位机（STM32）= 电控。
> 参考实现：`host/protocol.py` ↔ `firmware/App/Src/protocol.c`，两端 CRC 必须一致。

## 1. 物理层

| 项 | 值 |
|---|---|
| 接口 | UART / USB-CDC 均可 |
| 波特率 | 115200 8N1（够用；要更高就 921600，两端一起改） |
| 连线 | TX↔RX 交叉，共地 |

## 2. 帧格式（大端）

```
+------+------+-----+-----+-----+-----------+--------+--------+
| 0xAA | 0x55 | SEQ | CMD | LEN | PAYLOAD…  | CRC_H  | CRC_L  |
+------+------+-----+-----+-----+-----------+--------+--------+
```

- `SEQ`：发送方自增序号，0–255 回绕，用于丢帧统计
- `CMD`：消息 ID
- `LEN`：payload 字节数，上限 64
- `CRC16`：**CCITT-FALSE**（poly=`0x1021`，init=`0xFFFF`），覆盖 `SEQ | CMD | LEN | PAYLOAD`

## 3. 消息定义

### 上位机 → 下位机

| CMD | 名称 | 频率 | Payload |
|---|---|---|---|
| `0x10` | `CMD_VEL` | 50 Hz | `<float32 v, float32 w>` — 线速度 m/s，角速度 rad/s |
| `0x11` | `CMD_MODE` | 变化时 + 1 Hz | `<uint8 mode>` |
| `0x12` | `CMD_ESTOP` | 事件 | 空 |

`mode`：

| 值 | 含义 | 行为 |
|---|---|---|
| 0 | IDLE | 电机断使能，可手推 |
| 1 | RUN | 跟随 `CMD_VEL` |
| 2 | ESTOP | 立即刹车，锁死直到重新下发 IDLE |
| 3 | CALIB | 电机不转，只回传编码器/红外，用于标定 |

### 下位机 → 上位机

| CMD | 名称 | 频率 | Payload |
|---|---|---|---|
| `0x80` | `FB_STATE` | 100 Hz | `<uint32 tick_ms, float32 v_l, float32 v_r, int32 enc_l, int32 enc_r, uint8 ir, uint8 status>` |
| `0x81` | `FB_ACK` | 收到即回 | `<uint8 acked_cmd>` |

`status` 位定义：

| bit | 含义 |
|---|---|
| 0 | 编码器已就绪 |
| 1 | 低电压 |
| 2 | 看门狗超时（最近 200ms 没收到上位机指令） |
| 3 | 急停生效 |
| 4 | 电机堵转 |

`ir`：五路红外循迹，`bit0` 最左 … `bit4` 最右，**1 = 压线**。

## 4. 安全规则（务必实现）

1. **看门狗**：下位机连续 **200 ms** 没收到合法帧 → 电机自动停转，`status.bit2` 置位。
2. **急停优先**：`CMD_ESTOP` 立即生效，且必须显式下发 `CMD_MODE=IDLE` 才解除，防止误恢复。
3. **CRC 错误丢帧**，不影响后续解析（解析器要能重新同步到 `0xAA 0x55`）。
4. **上电默认 IDLE**，绝不默认 RUN。

## 5. 为什么这么设计

- **固定帧长 + 校验**：比赛现场电机干扰大，纯文本协议（`$V,0.3#`）容易解析错位。
- **100 Hz 上行**：算法侧做视觉时也要知道轮速，反馈慢了融合就没意义。
- **`FB_STATE` 里带 `enc_l/enc_r`**：里程计算在上位机做，方便以后换算法。
- **200 ms 看门狗**：视觉进程崩了，车自己停，不至于冲出场。
